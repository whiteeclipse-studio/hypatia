# Core UI — Implementation rules

Part of the [design proposal](README.md). See [mockups](mockups.md) for visual examples and the [component catalogue](components.md) for each study's purpose and candidates.

## Overview

These rules propose a complete Core UI theme, styled component library, and native Obsidian adaptation using the previous implementation as a visual reference. They define the intended defaults and component responsibilities for the rewrite. Historical captures illustrate earlier states; they do not verify the new implementation.

The proposed foundation is React and Radix Themes, with Primitives used internally where needed. The former prototype used Themes 3.3.0; that historical version does not select the version for the rewrite. Technical delivery is proposed in draft [RFC-0002](0002-tech-stack.md#core-ui-theme-and-component-library). The [Radix Themes guide](https://www.radix-ui.com/themes/docs/overview/getting-started) describes its styled components and theme boundary.

## Requirement terminology

Uppercase requirement keywords follow IETF **BCP 14**, as defined by [RFC 2119](https://www.rfc-editor.org/rfc/rfc2119) and clarified by [RFC 8174](https://www.rfc-editor.org/rfc/rfc8174). **MUST**, **MUST NOT**, **REQUIRED**, **SHALL**, **SHALL NOT**, **SHOULD**, **SHOULD NOT**, **RECOMMENDED**, **NOT RECOMMENDED**, **MAY**, and **OPTIONAL** carry those meanings only when written entirely in uppercase. They specify the proposed design, not owner approval.
